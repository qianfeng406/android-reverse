# 控制流反混淆工具开发计划

## 目标和验收层次

开发分为两个层次。**工具 demo** 用 `lesson_score` 验证阶段 0–6 可以连续运行：从指定函数和样本出发，产出 trace、结构候选、定点采集、转移规则、修复计划和验证报告。它只证明工具骨架与这一类样本的策略有效，不代表已能处理其他混淆。

**工具增强** 在稳定的阶段接口上逐个增加识别、溯源、推导及修复策略。每增加一种能力，都用新样本和已有样本回归验证，明确支持范围和未解决项。阶段数据契约见 [开发文档](DEVELOPMENT.md)。

## 第一部分：打通工具 demo

以下工作按依赖顺序推进。每项的输出都由下一项直接读取；不使用人工填好的业务块名单作为输入。

| 里程碑 | 开发内容 | 可检查的交付物 | 通过条件 |
| --- | --- | --- | --- |
| D0 工程骨架 | 建立命令行入口、配置、阶段目录与 JSON Schema；加入 `binary_id + module_offset`、证据引用及 `ModelAdapter` 接口 | 可运行的流水线命令、各阶段空实现、格式校验和固定提案重放适配器 | 错误输入、版本不一致和缺失阶段产物会明确报错；可从任一已保存阶段继续运行；无模型连接也能重放 |
| D1 静态基准与粗采集 | 导出 ARM64 指令和静态块；迁入 Frida 采集，保留块起止、调用边界、线程/调用 ID 和原始事件 | `binary_manifest`、`instruction_table`、`static_cfg`、`raw_trace` | 同一二进制的多次运行可按模块偏移合并；原有 7 组输入可重放；无跨调用串线 |
| D2 结构发现 | 建观察图；组合回边、状态读取、比较链和写入回流证据；输出候选及反例；接入只读 `codex_exec` 提案适配器 | `structure_candidates`、`probe_plan`、可视化图、模型提案及校验记录 | 无需预填地址即可为 `lesson_score` 提出正确的状态位置、回跳块和分发区域；真实循环不会仅因高频被判为分发器；模型提案可重放 |
| D3 定点采集 | 根据计划在条件计算、状态写入与分发读取点采值；与实际目标逐次配对 | `transition_observations` | 四个分叉来源均能记录条件输入、所选状态和到达目标；结果能与原始 block trace 对齐 |
| D4 转移推导 | 实现 ARM64 最小表达式解释器及比较链分发策略；核对动态观测 | `transition_rules`、未解规则报告 | 推出 demo 中单后继与双后继规则，区分已观察与已静态证明；制造缺失或冲突记录时不输出伪确定结果 |
| D5 修复与验证 | 检查待绕过指令的副作用，生成可撤销修复计划；在样本副本上实施最小二进制 patch，并导出 IDA 可查看的修复 CFG | `patch_plan`、修复样本、验证报告 | 原件不变；可从原始样本重现修复；已选输入的返回值及指定副作用一致；失败可撤销并定位到规则/修改项 |

### Demo 完成判据

1. 从干净环境按文档命令执行 D0–D5，不需要人工逐块标注或手填跳转表；唯一必须指定的是二进制、目标函数与测试输入。
2. 每条输出边能回溯到指令和运行事件；不确定边保持 `unresolved`，不进入自动修复。
3. 对 `lesson_score` 生成可审阅的修复前后 CFG、修复清单和差分报告；可撤销修改。
4. 同一组固定夹具重跑得到相同的结构化产物。模型参与时保存模型提案，使用固定提案重放验证，避免测试结果依赖实时模型输出。
5. README 说明安装、运行、阶段产物位置和已知支持范围。通过这些条件即宣布“工具 demo 可运行”，不将其称为通用反混淆工具。

## 第二部分：扩展策略和适用范围

增强按**机制**组织，而非为每个样本写完整专用脚本。先建立样本矩阵与统一评价方法，再逐项扩展。

| 优先级 | 新机制 | 主要扩展位置 | 新样本验收重点 |
| --- | --- | --- | --- |
| E1 | 状态常量经过算术、异或或多条指令编码 | `strategies/state`、表达式简化 | 正确恢复状态表达式，不把单次观测值误作常量规则 |
| E2 | `BR/BLR`、地址表、函数返回值参与目标计算 | `strategies/indirect`、跨块及跨调用切片、定点探针 | 记录实际目标，解释目标来源和调用副作用 |
| E3 | 多个局部分发器、分层分发与共享回跳 | 结构发现和区域归属 | 区分分发区域与跨区域转移，避免错误折叠 |
| E4 | 分发块夹带业务计算、状态更新跨块 | 指令级副作用分析与修复规划 | 保留必要指令；无法安全绕过时拒绝自动修改 |
| E5 | 虚假控制流、不透明谓词与指令替换叠加 | 谓词证明、表达式简化、修复策略 | 能识别假边及等价运算，不以有限 trace 代替证明 |

每项按相同流程开发：加入一个可复现样本和未混淆对照或可检查的行为基准；保存采集夹具；实现策略；运行新样本及全部旧样本；记录成功、未解、误判、运行开销和采集开销。真实样本用于检验适用性，但不能在缺少真值时把“图变简单”单独当作正确性标准。

## 大模型接入计划

大模型接入使用统一的结构化提案接口，而不是直接改图或 patch。

1. 在 D2 中读取图摘要、反汇编切片和证据，提出候选分发区域、状态位置及识别规则；规则引擎独立核查。
2. 在 D3–D4 中接收未解决切片，提出新采集点或溯源策略；新策略先在固定夹具上验证，再纳入策略库。
3. 在 D5 中复核混合块副作用与失败报告；最终能否修改由指令检查和差分验证决定。

首个 demo 可使用可保存、可重放的模型提案；自动化回归不依赖模型每次给出相同措辞。记录模型输入摘要、提案、验证结果与成本，便于评估模型是否真正减少未解项。

## 开发顺序与维护方式

先完成 D0–D5 的纵向流程，再进入 E1–E5。若某阶段暴露通用数据结构问题，先修接口并迁移旧夹具；若只是新混淆形态，新增策略和样本，不修改已有证据的含义。每个里程碑单独记录实现、测试和局限，并同步更新 [使用说明](USAGE.md) 与上方状态表。版本控制优先提交源码、文档、小型夹具及可重放配置；设备原始数据、大型二进制和本地 IDA 数据库按需单独存放。
